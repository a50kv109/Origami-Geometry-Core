## 4. Подтверждённая причина ошибки экспорта Remix («Запрос содержит недопустимый аргумент»)

### 4.1. Механизм экспорта Google AI Studio Remix
Кнопка экспорта в Remix отправляет коммит на GitHub не через стандартный локальный бинарник `git push`, а через **GitHub REST API** (создание дерева объектов `POST /repos/{owner}/{repo}/git/trees` и передача содержимого файлов через `POST /repos/{owner}/{repo}/git/blobs`).

### 4.2. Жесткие ограничения GitHub REST API
1. **Предел размера одиночного блоба:** GitHub API строго ограничивает размер передаваемого через API файла до **25 MB**.
   - Файл `Invitation_to_Creative_Playing_with_Origami_44ee61f2.pdf` имеет размер **57 MB**.
   - Файл `Solid_Origami_3b32bc97.pdf` имеет размер **50 MB**.
   - При попытке создания Git Tree с объектом > 25 MB GitHub API немедленно возвращает HTTP-статус `422 Unprocessable Entity` с телом ошибки `Invalid argument` («Запрос содержит недопустимый аргумент»).
2. **Дублирование в каталоге `dist/`:**
   - Команда сборки Vite копирует всё содержимое `public/assets/` в `dist/assets/`.
   - В результате файлы 57 MB и 50 MB присутствуют в дереве проекта **в двух экземплярах** (в `public/` и в `dist/`), суммарно превышая 200 MB.
3. **Область видимости экспорта:**
   - Кнопка Remix экспортирует **корень всего рабочего пространства** (`/app/applet`), а не только подкаталог `skilla/`.
   - Пользователь пытается опубликовать репозиторий под именем `skilla` (или `a50kv109/skilla`), но платформа пытается загрузить весь монолит PCRS со всеми книгами и дистрибутивом.

## 5. Безопасный план перехода к публикации без потери цитируемости

### 5.1. Принцип сохранения цитируемости (Zero Loss Provenance)
В современной математике, инженерии и Open Science валидность доказательств и воспроизводимость **не требуют хранения сканов оригинальных книг внутри репозитория исходного кода**.

Цитируемость и доказательная база полностью сохраняются через:
1. **Точные библиографические паспорта** (`FUJIMOTO_CONSTRUCTION_PASSPORT_01..03.md`, `MURRAY_RIGNEY_CONSTRUCTION_PASSPORT_01.md`).
2. **Точные ссылки на страницы, параграфы и номера рисунков** (например, Фудзимото, с. 10–13, рис. 1–6; Маррей–Ригни, с. 166–185).
3. **Формальные математические спецификации и инварианты** в коде и тестах (`PRIMITIVE_B_INDEPENDENT_AUDIT.md`, `pointToPointVerifier.ts`).
4. **Криптографические хэши (SHA-256)** исходных модулей в `SOURCE_MANIFEST.md`.

Все PDF-файлы остаются сохранными в рабочей среде Remix для продолжения лабораторной работы в PCRS, но исключаются из публичного дерева Git.

### 5.2. Пошаговый план подготовки к экспорту (без удаления файлов)

#### Шаг 1. Рассмотрение и утверждение данного аудита (Текущий статус)
Пользователь и команда лаборатории верифицируют выводы аудита. Никакие файлы в среде не удаляются и не модифицируются.

#### Шаг 2. Разделение областей экспорта (Два возможных сценария)

- **Сценарий А (Рекомендуемый для Remix): Изоляция корня публикации**
  Если платформа Remix экспортирует корень проекта, необходимо обеспечить, чтобы экспортер игнорировал тяжелые файлы.
  Для этого в корневой `.gitignore` должны гарантированно входить:
  ```gitignore
  # Первичные книги и тяжелые ассеты
  public/assets/aistudio/*.pdf
  public/assets/aistudio/*.zip
  public/assets/fujimoto/
  public/assets/fujimoto_back/
  public/assets/invitation/
  public/assets/invitation_ch7/
  public/assets/twist3/
  
  # Сборочные директории
  dist/
  dist/*
  
  # Локальные архивы
  *.zip
  skilla.zip
  ```

- **Сценарий Б: Автономный экспорт специализированного репозитория `skilla`**
  Поскольку репозиторий `skilla` спроектирован как самостоятельный модуль (`/app/applet/skilla/`), идеальной публикацией на GitHub является именно содержимое директории `skilla/`, содержащее свой собственный `package.json`, `README.md`, `LICENSE`, `src/` и `docs/`.
  - Скачивание чистого архива `skilla` через интерфейс для создания чистого репозитория `a50kv109/skilla`.
  - Либо публикация родительского репозитория как `PCRS-Research-Lab` (после закрытия маской `.gitignore` тяжёлых PDF), а подкаталога `skilla` — как обособленного репозитория.

#### Шаг 3. Контрольная проверка перед повторным нажатием кнопки
Перед инициацией коммита через кнопку Remix убедиться:
1. Размер формируемого payload не превышает лимит GitHub API (25 MB на файл, суммарно < 50 MB на коммит).
2. Оригинальные PDF остаются нетронутыми в `public/assets/aistudio/` и доступны для работы ассистента в Remix.
3. Все ссылки в паспортах проверены и указывают на библиографические первоисточники.

## 6. Резюме

1. **Причина сбоя:** Превышение лимита GitHub REST API (25 MB) из-за попытки отправки двух PDF-книг (57 MB и 50 MB) и каталога `dist/` (167 MB) из корня проекта.
2. **Вложенные `.git`:** Отсутствуют; они не являлись причиной ошибки.
3. **Безопасность данных:** Ни один первоисточник не удаляется и не изменяется. Исследовательская среда сохраняет 100% исходных материалов.
4. **Готовность:** После согласования плана можно применить точечные настройки исключения экспорта.
