# PCRS — ARCHITECTURAL LESSONS FROM AI GEOMETRY SKILL 2

Данный документ описывает архитектурные принципы, заимствованные из репозитория `AI Geometry Skill 2` для улучшения PCRS. Эти принципы являются методологическими ориентирами и не означают, что PCRS уже обладает данными возможностями.

## 1. Заимствуемые принципы

1.  **Модель возможностей (Capability Model):**
    - Использование формальной классификации возможностей (например, G0–G4 для уровня геометрической сложности).
    - PCRS может заимствовать эту иерархию для формализации границ MVP.
    - *Источник:* `docs/CAPABILITY_MODEL.md`

2.  **Происхождение объектов (Provenance):**
    - Каждая геометрическая сущность должна иметь цепочку происхождения: гипотеза → геометрический примитив → реализация → верификация.
    - *Источник:* `docs/PROVENANCE_EPISTEMIC_MODEL.md`

3.  **История построения (Construction History):**
    - Построение паттерна — это не только конечный результат, но и история преобразований (трасса). Она необходима для проверки инвариантов на каждом шаге.
    - *Источник:* `docs/REASONING_GUIDANCE_PATTERNS.md`

4.  **Статусы доказательности (Epistemic Statuses):**
    - Строгое разделение: `PROPOSED`, `EXPERIMENTAL`, `VERIFIED_BY_TEST`, `CANONICAL`.
    - Это улучшает прозрачность системы.
    - *Источник:* `docs/AI_GEOMETRY_SKILL_PASSPORT.md`

5.  **Контракты инструментов (Skill Contracts):**
    - Интерфейс для взаимодействия с инструментами (например, `validate_preconditions`, `execute_pattern`) позволяет агентам использовать возможности системы, не зная деталей реализации.
    - *Источник:* `API.md`

6.  **Границы ответственности:**
    - Четкое разделение того, за что отвечает ядро, а за что — агент.
    - *Источник:* `docs/SKILL_CONTRACT.md`

## 2. Применение в PCRS
Эти принципы будут постепенно внедряться в реестр документации PCRS по мере разработки архитектурных решений, не затрагивая при этом уже замороженные вычислительные модули (`reflection.ts`, `independentVerifier.ts`).
